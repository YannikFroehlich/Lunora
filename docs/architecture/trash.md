# Trash

Moved out of CLAUDE.md, which keeps the summary and the cross-cutting rules ([CLAUDE.md](../../CLAUDE.md)).

Deleting a task (`task_delete`), events (`calendar_event_delete` with its series scope, `calendar_event_delete_series`), a habit, a vocabulary list or a recipe goes through `app/services/trash.py`: `trash_task`/`trash_events`/`trash_habit`/`trash_vocabulary_list`/`trash_recipe` store a `django.core.serializers` snapshot of the rows (task + subtasks, shares, comments, time entries with a running timer stopped; events + attendees, comments; habit + checks; list + cards, shares; recipe + meal plan entries) in one `TrashedItem` and then really delete them, so no query on the live tables needs a trash filter. `_restorable` is table-driven: `ROOT_OWNER` names each deleted model's owner field, `CHILDREN` each dependent row's parent field and the people who must still exist. `/trash/` (`trash_views.py`, kinds gated by `KIND_FLAGS`: `tasks`, `calendar_event_creation`, `tools`) restores with the old primary keys via `force_insert` (feed UIDs and inbox source keys stay valid); `_restorable` first cuts references to lists, labels, a parent task and people that are gone, and `restore_item` re-runs `sync_event_reminders`. `run_scheduled_tasks` purges items after the notes' `TRASH_RETENTION`. Delete paths report through `trashed_message` (`trash_views.py`), whose `trash-undo-<id>` message tag makes `base.html` render a "Rückgängig" soft form that restores and returns via `return_to`; the flash class reads `message.level_tag`, not `message.tags`, so extra tags don't spoil it. A new model hanging off a trashed one needs adding to its snapshot and to `CHILDREN`; a new kind needs a `KIND_CHOICES` entry (migration), `KIND_FLAGS`/`KIND_ICONS`, and its delete path should call its `trash_*` function plus `trashed_message` instead of `.delete()`.
